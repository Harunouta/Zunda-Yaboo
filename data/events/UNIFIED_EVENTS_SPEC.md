# Zunda-Yaboo 統合イベントデータ作成・変換仕様書

## 1. 概要
本仕様書は、Zunda-Yabooの歴史シミュレーションエンジンにおけるイベント追加を効率化するための「統合データ（Excel/CSV）」のフォーマットと、その変換手順を定義するものです。

本来、Zunda-Yabooへのイベント追加には `timeline.csv` と `catalog.yaml` の2ファイルを同期して編集する必要がありますが、本仕様に基づく統合データを作成し、専用のHTML分割ツールを通すことで、Cursor等のAIエディタでも安全かつ一元的にデータを生成・管理できるようになります。

## 2. ワークフロー
1. **データ生成・編集**: Cursor（または人間）が、後述の【3. カラム定義】に従い、Excelファイル（例: `categorized_events.xlsx`）の各シート、または統合CSV（`unified_events.csv`）に1イベント1行でデータを追記する。
2. **CSVエクスポート**: Excelで編集した場合は、対象のシートを「CSV（カンマ区切り）」として書き出す。
3. **ファイル分割**: ブラウザで `converter.html` を開き、CSVを読み込ませて以下の3ファイルを生成・ダウンロードする。
   - `timeline.csv` (発火月とIDの紐付け)
   - `catalog.yaml` (プロンプトや被害係数の定義)
   - `sources.txt` (Wikipedia等の引用元一覧)
4. **プロジェクトへの適用**: 生成されたファイルを Zunda-Yaboo の所定のディレクトリ（`japan/` など）に配置する。

---

## 3. カラム定義（全10列）
統合データのCSV/Excelは、以下の10列（A〜J列）で構成されなければなりません。ヘッダー名は正確に一致させてください。

| 列番 | カラム名 | 必須 | 型・制約 | 出力先 | 説明 |
|:---|:---|:---:|:---|:---|:---|
| A | **yearMonth** | 必須 | `YYYY-MM` | timeline | イベントの発火月。必ず4桁年と2桁月をハイフンで繋ぐ（例: `1853-07`）。 |
| B | **eventId** | 必須 | 半角英数字・スネークケース | timeline, catalog | イベントの一意な識別子（例: `perry_arrival`）。他のイベントと重複してはならない。 |
| C | **scope** | 必須 | `japan`, `japan_info`, `world` | timeline, catalog | 影響範囲。日本国内の出来事は `japan`、噂や事前情報は `japan_info`、外部ショックは `world`。 |
| D | **notes** | 任意 | 文字列 | timeline | 管理用のメモやイベントの和名（例: `大坂夏の陣`）。シミュレーション内部では使用されない。 |
| E | **promptForLeader** | 必須 | 文字列 | catalog | 首領（AI）向けのプロンプト。状況を短く具体的に記載する。 |
| F | **promptForOpinionLeader** | 必須 | 文字列 | catalog | 庶民・オピニオンリーダー向けのプロンプト。噂や断片的な情報として記載する。 |
| G | **disasterOverride** | 任意 | 数値 (`0.2` 〜 `1.0`) | catalog | 災害の強度。値が小さいほど凶作などのダメージが大きい。未指定（空欄）の場合は気候のみ反映。 |
| H | **populationShock** | 任意 | 小数 (`0.0` 〜 `1.0`) | catalog | その月の人口減少率（例: `0.008` = 0.8%減）。 |
| I | **cropLossExtra** | 任意 | 小数 | catalog | 収量・備蓄への追加ダメージ係数。 |
| J | **sourceUrl** | 任意 | URL | sources | イベント作成時に参考にしたWikipedia等のURL。CC BY-SAの引用元明記に使用される。 |

## 4. Zunda-Yaboo エンジン制約事項（Cursorへの指示事項）
AI（Cursor）に新規イベントの作成を依頼する際は、本仕様書とともに以下の制約を守らせてください。

1. **粒度と scope の使い分け**:
   - 世界史のフル年表は作成しない。「その月、日本ノードの統治／噂／物価に効くか？」を基準に取捨選択すること。
   - まだ日本に到達していないが、長崎経由などで情報だけが入る場合は `scope: japan_info` を用いること。
2. **同一月の複数発火**:
   - 同じ月に複数のイベントが起きる場合（例: 浅間山噴火と天明の大飢饉）、`yearMonth` を同一にした別々の行として作成して構わない。
3. **未実装機能の拡張について**:
   - Zunda-Yabooには `epidemicSeverity` (疫病) や `worldEffect` (ハイパーインフレ等の特殊効果) のキーも存在するが、現在の10列フォーマットには含まれていない。これらの効果を付与したい場合は、出力後の `catalog.yaml` を手動で微調整するか、将来的にCSVフォーマットの列拡張（K列、L列など）を行うこと。
4. **データの位置づけ**:
   - 本シミュはフィクション用である。日付や説明は Wikipedia 等と LLM 推論を混ぜてよく、史実照合や「事実と一致させること」は設計目標ではない。

---

## 5. 変換ツールの動作仕様
- ツール（`converter.html`）は、ダブルクォーテーション `"` で囲まれたセル内の改行やカンマ `,` を正しく処理する。プロンプト（E列・F列）内にカンマが含まれていても問題ない。
- `sources.txt` の生成時には、クリエイティブ・コモンズ（CC BY-SA）ライセンスの定型文が自動的にヘッダーとして付与される。
