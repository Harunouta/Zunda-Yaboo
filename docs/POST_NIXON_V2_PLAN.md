## 1. 制度の答え（再掲・短く）

ニクソン以降は単純なドル本位ではない。

- 〜1971-08: 円の対ドル **360 固定**（国際枠はブレトンウッズ）  
- 1971-08: 金兌換停止 → 過渡  
- 1971-12〜: **スミソニアン 308**（暫定固定）  
- **1973-02〜: 管理フロート（円）**。ドルは国際決済の中心でも国内本位ではない  

→ エンジンは **円マネー + 対ドル為替レジーム**。表示も円。

## 2. 提案: ラベルだけ vs `yen_float` Enum

**推奨: Enum までやる**（データ増えてよい・LLM可読・円表示と整合）。

| standard（Enum） | いつ | 意味 |
|------------------|------|------|
| `yen_usd_peg` | 1949-04〜1971-11 頃 | 固定（360。過渡月はイベント） |
| `smithsonian_peg` | 1971-12〜1973-01 | 308 暫定固定 |
| `yen_float` | 1973-02〜2026-08 | 管理フロート |
| （互換）`dollar` | 非推奨エイリアス | 旧セーブ／CLI のため残してもよい |

ログ例（LLM 向け）:

```json
"monetaryStandard": "yen_float",
"fxRegime": "managed_float",
"moneyUnit": "円",
"fxYenPerDollar": 240.0,
"policyRateAnnualPct": 5.0,
"policyRateKind": "boj_discount_or_call"
```

物理の芯は当面「既存 dollar 月次の改名・円建て」でよい。名前だけ `yenNotes` / `fxReserves` に寄せる。

## 3. 金利 — 「いつから使うか」

### 3.1 結論

**概念は全時代にあるが、系列の種類が時代で違う。**  
一つの「政策金利」を 1603 から連続させるのは嘘になる。代わりに **`policyRateKind` を時代で切り替える**。

| 時代 | 何を載せるか | 出典の性質 | エンジンでの使い方（薄く） |
|------|--------------|------------|---------------------------|
| 江戸〜幕末 | **民間貸付・家質の年利アンカー**（疎） | 論文の区間平均（大阪・江戸 家質 およそ年 3–15% 帯、幕府上限など） | `creditCost` → 投資・備蓄・不安に弱い係数。**日銀政策ではない** |
| 1882〜戦前 | **日銀公定歩合** | BOJ IMES Historical Statistics CSV（本店 1882–1941） | 同じフィールドに載せる。`policyRateKind=boj_discount` |
| 戦後〜1970s | 公定歩合／規制金利時代 | BOJ 時系列・百年史系 | 同上 |
| 1980s〜 | 無担保コール等 | BOJ FM02 月次など | `policyRateKind=uncollateralized_call` |
| 1999〜 | ZIRP / QE は **水準＋フラグ** | 実日付 | `policyStance: zirp\|qe\|…`（金利だけでは足りない） |

江戸は「分からん」ではなく、**月次の一国政策金利としては無いが、町人金融の利率サンプルはある**。  
→ `data/economy/interest_rate_anchors.csv` に  
`year,month,annualPct,kind,evidence,note`  
を積み、月次は補間。LLM には `kind` と `evidence` をそのまま渡す。

### 3.2 リアリティについて

- **あるとよい:** フロート期の「高い金利／ゼロ金利」が信用・投資ノブになる  
- **やりすぎない:** DSGE やイールドカーブは不要。月次は **1本の proxy 金利 + stance タグ**

## 4. 為替介入を「政策イベント」にするか？

### 4.1 推奨: **はい、政策イベント（＋手札）に加える**

理由:

1. プラザ・ルーブル・ニクソン過渡は **日付付きの史実行動** → 既存の政策／世界史イベント型と相性が良い  
2. エンジンに「常時介入アルゴリズム」を硬く書くより、**YAML で強さ・方向を読める**方が LLM 向き  
3. 法令カタログと同様、首領が選んでも無視してもよい **手札／史実自動** の二段にできる  

### 4.2 スキーマ案（LLM 可読）

`data/events/policies/` または japan イベントに:

```yaml
plaza_accord_1985:
  title: プラザ合意に伴うドル売り・円買い介入
  historicalYearMonth: "1985-09"
  kind: fx_intervention
  effects:
    fxInterventionDirection: sell_dollar   # 円高方向
    fxInterventionStrength: 0.6          # 0–1
    fiatTrustNudge: 0.02
  promptForLeader: 協調介入でドル安・円高を誘導する局面だ。準備と国内信用のバランスを取れ。
  notes: Plaza Accord 1985-09. evidence=real_date inferred_strength
```

エンジン側はメディエータに写すだけ:

- `fxInterventionStrength` → その月の FX をアンカー方向へ追加で寄せる／reserves を動かす  
- 平常月は **介入イベント無し**（勝手に毎日介入しない）

固定相場期（360/308）の「防衛介入」も同スキーマで、ニクソン直後などに置ける。

### 4.3 エンジン常時介入との役割分担

| | 政策イベント介入 | 常時フロート物理 |
|--|------------------|------------------|
| いつ | 史実月・手札選択時 | なし、またはごく弱い平均回帰 |
| 強さ | YAML で明示 | クリップ小さめ |
| LLM | プロンプトに載る | ログの数値だけ |

**推奨:** イベント主導。常時介入は最初は入れない（発散防止）。
